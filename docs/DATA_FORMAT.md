# 本地资料与字段格式

[返回项目介绍](../README.md) · [使用与配置](USAGE.md)

## 当前资料能力

离线 Mock 和本地资料＋真实模型模式，读取 `agent_demo/data/sources.json` 内置的 **2024 新能源汽车公开资料摘录快照**。本地“检索”是对快照做查询词、来源类别、发布日期和主体筛选，不是联网下载原网页。

两类受控任务为行业综述与公司财务对比，研究期 2024、观察截止 2025-03-31。它们共享快照，具有分别定义的章节与最低依据要求。**当前没有任意文件上传入口**，也没有 PDF、Word、Excel 或任意文本的通用解析器。网页中的 PDF 按钮是报告导出，不是资料上传。

开发者可直接维护 UTF-8 JSON，但 **只替换 `sources.json` 不会让本地模式支持任意新主题**：规划校验在 `providers.py`，可比口径、章节、派生规则与发布门槛在 `report.py`，规则写作也按既定任务组织。若要研究其他主题，先使用联网研究 Agent；若开发另一套本地案例，须同步适配这些契约。

## 文件结构示例

`sources.json` 顶层是数组，每一项是一份资料。下面使用虚构主体和 `example.org` 说明字段结构，**不是真实研究证据，不应直接加入正式样例；也不会满足现有发布门槛**。

```json
[
  {
    "source_id": "EX01",
    "title": "虚构公司2024年演示公告",
    "publisher": "虚构公司（仅格式示例）",
    "published_at": "2025-03-20",
    "source_url": "https://example.org/reports/demo-2024",
    "source_kind": "announcement",
    "entity": "虚构公司",
    "scope": "虚构公司合并报表；人民币；仅格式演示",
    "period": "2024",
    "value_type": "actual",
    "origin": "public_snapshot",
    "retrieved_at": "2026-10-23",
    "verification_status": "虚构示例，不代表已核对真实原文",
    "local_file": "data/sources.json",
    "locator": "EX01",
    "excerpts": {
      "年度业绩": "演示营业收入为12.5十亿元。"
    },
    "fields": [
      {
        "metric": "营业收入",
        "locator": "年度业绩",
        "pattern": "营业收入为([\\d.]+)十亿元",
        "unit": "十亿元",
        "category": "number"
      }
    ],
    "tags": ["新能源汽车", "2024", "虚构公司"]
  }
]
```

其中 `fields[].pattern` 是 Python 正则表达式字符串。JSON 内的反斜杠需要转义，代码实际拿到的表达式为 `营业收入为([\d.]+)十亿元`。抽取取 **第一个捕获组 `group(1)`**，所以必须有捕获组，且只把所需数值或文字放在第一个组内。

代码中的字段名称是 `pattern`，不是 `regex`。`fields[].locator` 须与 `excerpts` 的键精确一致；同一摘录可供多个字段使用。

## 资料级字段

| 字段 | 类型与作用 |
| --- | --- |
| `source_id` | 唯一资料 ID；用于事实、引用和证据定位，不应重复 |
| `title`、`publisher` | 标题与发布主体，界面展示来源信息 |
| `published_at` | `YYYY-MM-DD`，用于研究日期窗口筛选 |
| `source_url` | 可公开访问的原始来源 URL；本地流程不会自动抓取它 |
| `source_kind` | `web`、`announcement` 或 `research`，对应本地工具筛选；当前无授权研报记录 |
| `entity` | 统计主体，默认由该资料下的字段继承 |
| `scope` | 完整统计范围，如合并报表、全球销量、国内零售等；影响可比键与是否进入特定章节 |
| `period` | 数据所属期间，区别于文件发布日期 |
| `value_type` | 可选，默认 `actual`；计划使用 `announced_plan` |
| `origin` | 资料来历标识，现有资料使用 `public_snapshot` |
| `retrieved_at`、`verification_status` | 快照采集日期与核对说明；不是运行时更新证明 |
| `local_file`、`locator` | 供界面显示本地文件与资料定位 |
| `excerpts` | `{定位名: 摘录文字}`；实际供抽取使用的文本 |
| `fields` | 要从摘录中抽取的字段数组 |
| `tags` | 字符串数组，与标题共同用于查询词筛选 |
| `synthetic_test` | 可选布尔值；合成异常测试标记，不能被人工采用为真实研究事实 |

本地工具会按来源类别、查询词、发布日期及可选公司条件过滤。一个结构正确的资料仍可能因不满足筛选条件而没有被检索到。不要为了通过筛选而给虚构资料伪造真实来源标识。

## 字段级格式与换算

| 字段 | 类型与作用 |
| --- | --- |
| `metric` | 指标名，例如“营业收入”或“国内零售份额”；须与报告契约使用的名称一致 |
| `locator` | 对应 `excerpts` 中的键 |
| `pattern` | Python 正则字符串；第一个捕获组为目标内容 |
| `unit` | 原始单位，如 `辆`、`万辆`、`亿元`、`十亿元`、`百万元`、`%`、空字符串 |
| `category` | `number` 或 `text`；文字原样保留，数值转为浮点数 |
| `entity`、`scope`、`period` | 可选，覆盖资料级默认值；适用于一份资料内多个主体或期间 |
| `value_type` | 可选，覆盖资料级事实类型 |
| `target_period` | 可选，供计划类事实记录计划目标期间 |

内置规则只做下列单位换算，其他单位原样保留：

| 原始单位 | 标准单位 | 乘数 |
| --- | --- | --- |
| 辆 | 万辆 | 0.0001 |
| 十亿元 | 亿元 | 10 |
| 百万元 | 亿元 | 0.01 |

抽取后保留 `raw_value`、`raw_unit` 和 `conversion_factor`，供证据面板显示。示例中的 12.5 十亿元会得到 125 亿元。比例与百分点不互换；份额变化按经审核的同口径前后两期份额相减，结果单位是“个百分点”。

## 事实类型与可比边界

同口径分组键为 `entity + metric + period + scope + value_type + unit`。相同键出现不同值会成为冲突；统计范围不同的数据不能仅因指标名相同就比较数值或计算份额。

本版区分 **已实现事实 `actual`** 与 **已宣布计划 `announced_plan`**。计划另保留目标期间，不会被直接写成已完成结果。派生份额变化还保留输入事实 ID、计算式和来源；只有两项输入都被本次人工采用、且均能进入对应章节上下文时才使用派生结果。

现有报告使用特定主体、期间、口径和类型的匹配规则。例如全国新能源汽车总销量（含出口等）不能直接充当国内乘用车厂商零售份额的分母；合并营收也不能直接视为单一汽车业务收入。

## 预算与上下文

- 本地抽取按每份资料 **2,000 字符**预算处理 `excerpts`；预算不足时跳过相应摘录，并保存 `processed_locators`、`skipped_locators`，不默默当作已读。
- 写作按每一章节 **12,000 字符、24 个来源片段**预算组织上下文。字符计数覆盖章节序列化后的事实与片段结构，不只是正文字符。
- 写作只接收经人工采用、非合成且适用于该章节的事实和片段；排除项、预算外条目与缺失项不会被补成事实。
- 本地规则报告还检查核心依据、引用、章节和长度；核心缺失会显示诊断而不发布。

这些是本地受控工作流的预算，不代表联网服务商的上下文窗口或 Token 上限。联网模式不读取此快照，而是使用实际检索返回资料，并在人工采用候选后另行构建写作输入。

## 修改资料时的最小自查

1. 保持 UTF-8、合法 JSON、唯一 `source_id`，核对原文和发布日期。
2. 确认每个字段的定位键存在、正则第一个捕获组确实能匹配目标内容、单位与类型准确。
3. 对照 `providers.py` 的主题与工具筛选、`report.py` 的章节与口径契约；不要把改了 JSON 当作已支持新主题。
4. 以新建离线任务检查检索、抽取、来源面板与审核结果；保留既有历史任务，不覆盖旧决定。

运行任务中产生的 `state.json` 等属于用户本地数据；仓库内必要的字段定义和安全示例不等同于私人任务历史。发布或分享时应逐项选择产物，避免上传完整个人输出目录。
